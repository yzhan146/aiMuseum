# AI Museum North Star

- 状态：已批准（含 API-first 与 3×12 首发规模补充；具体名单待 Stage 2 v2 批准）
- 日期：2026-07-16
- 下一阶段：Stage 2 PRD

## 一句话愿景

AI Museum 是一个开源、可扩展的历史人物运行平台：平台为所有人物提供统一的可信对话、长期记忆、知识图谱、时间线、人物关系、语音与受控媒体创作能力；社区通过声明式人物包、史料上传与人工审核持续创造和维护人物，而访客可以和这些人物建立连续、可追溯、适龄的学习关系。

## 产品形态

产品由三层组成：

1. **开源平台**：提供人物运行时、对话、记忆、检索、引用、图谱、时间线、Agent Task、Provider、权限、评测和创作工具。
2. **可扩展人物包**：人物身份、认知边界、来源、Claim、关系、人格、媒体许可和评测均以声明式版本化数据表达，不携带任意可执行代码。
3. **社区与访客体验**：维护者用模板或创作台创建、更新人物；访客与已发布人物对话、探索关系网络并沿学习路线继续。

公开 MVP 初始发行提供至少3个按历史时期组织的人物组，每组12个达到统一发布门槛的可对话人物，共至少36个唯一人物。它们使用与社区人物完全相同的声明式协议和运行接口，不把首发内容写死在应用中。

## 目标用户

### 第一优先：9–12 岁中文学习者

- 已具备基础阅读和表达能力，对科学、历史和人物故事有强烈好奇心。
- 需要更短、更清楚、可继续追问的解释，也可能更偏好语音交互。
- 需要严格的未成年人隐私、安全、适龄表达和敏感记忆限制。

### 第二优先：陪伴和组织学习的人

- 家长、教师、博物馆教育人员。
- 希望知道孩子学过什么、接下来适合探索什么，但不应默认获得孩子的全部私聊内容。

### 供给侧用户

- 开源贡献者、历史研究者、科普作者、教师、博物馆与文化机构。
- 通过标准模板、Git 或网页创作台创建人物、维护史料和提交新版本。

### 治理侧用户

- 人物包维护者、史料审核者、许可审核者和平台管理员。

## 核心问题

- 静态历史内容碎片化，难以形成持续探索和人物关系理解。
- 普通角色聊天没有长期关系，切换人物后上下文丢失。
- LLM 容易产生无来源断言、混淆身后事件或越过人物认知边界。
- 高质量人物创建需要大量史料整理、实体消歧、关系构建和许可判断。
- 完全共享人物私聊破坏隐私和角色真实感，完全隔离又无法形成全局学习进度。
- 现有数字人产品往往把形象生成、声音模仿和史料使用许可混为一谈。

## 为什么是现在

- 大模型已能提供自然表达，差异化开始转向可信性、连续性、记忆和可解释性。
- 多模态模型使 OCR、转录、Claim 提取和历史场景辅助创作成为可组合能力。
- Agent 适合长任务编排，但人物对话仍需要低延迟和确定性边界。
- 用户和机构对 AI 幻觉、未成年人隐私、版权与数字人格冒充更加敏感。
- 开源协议和声明式人物包有机会让机构与社区共同维护知识，而不被单一模型供应商锁定。

## 短期 MVP 目标

证明一个核心闭环：

> 9–12 岁访客能够在3个历史时期、至少36位可信人物之间持续对话与收集；每个事实可追溯、每次自然回忆有来源、切换人物不丢历史，并能通过人物关系和时间线继续探索。

MVP 同时证明供给侧最小闭环：第三方不修改平台代码即可基于模板创建一个私有人物包、导入史料、审核候选 Claim、试聊并导出。

MVP 采用 **LLM/API-first** 方案：真实模型 API 和 Embedding 是正式体验的必备能力，而不是发布后的可选增强。LLM 负责问题理解、适龄表达、摘要、记忆候选、知识候选提取和受约束 Agent 规划；人物历史事实仍必须来自已审核 Claim 与证据，不能直接使用模型参数知识补写。规则与 Mock 模式只服务于自动化测试、开源贡献者开发和 API 故障诊断，不代表正式 MVP 体验。

## 长期目标

- 形成开放、可迁移、可治理的历史人物生态。
- 社区和机构共同维护人物版本、史料、争议观点、时间线和关系网络。
- 平台从可信文字/语音对话逐步扩展到合影、插画、导览和历史场景视频。
- 平台基于已收集资料与可信公开网络信息发现补充来源，但所有新知识仍必须保留来源、许可和人工审核门禁。
- 用户在多个人物之间形成长期历史学习旅程，而不只是一次性角色聊天。

## 核心原则

1. 人物是受约束的 Character Chat Runtime，不是能自由联网和任意调用工具的自主 Agent。
2. 专业 Agent 由确定性协调器调度，只能使用白名单工具。
3. 正式历史知识的核心单位是带证据的 Claim，不是无来源的“事实”。
4. 网络公开信息只能成为 Source 与 Candidate Claim，不能直接写入正式图谱。
5. 知识图谱按人物包版本永久留存；撤销来源时保留审计记录，但从可回答索引退出。
6. 用户原始消息作为个人档案尽量长期保存；compact 生成派生摘要，不覆盖或销毁原文。
7. 人物关系记忆按用户与人物隔离；全局只共享显式画像和不含来源的掌握度信号。
8. 用户可查看、纠正、暂停、导出和删除个人记忆与历史。
9. 9–12 岁托管服务默认最小化收集，不推断或自动启用敏感画像。
10. 人物包、媒体和平台代码分别声明许可；上传素材不自动授权声音或形象生成。
11. 正式 MVP 至少接入一个生产级 Model Provider 与 Embedding Provider；平台接口保持供应商可替换，密钥仅保存在服务端。
12. 所有模型输出均视为候选结果：对话回答需通过引用与边界核验，记忆和知识需通过各自的确认门禁。

## 成功定义

项目不以回访率、停留时长或对话条数作为主要目标。MVP 重点验证质量、安全和可扩展性：

- 公开历史断言 100% 可追溯到已审核 Claim 和有效来源。
- 每条长期记忆 100% 可追溯到用户消息或显式输入。
- 严重人物边界、隐私泄露和跨人物记忆泄露测试通过率 100%。
- 关键历史问题的 Claim 支持准确率达到约定评测阈值。
- compact 后的对话连续性与原始记录保持一致。
- 模型回答具备流式体验、可观测调用链和可复现的 Prompt/模型版本记录。
- API 失败、限流或超时时不伪造回答，并向用户提供明确的重试或稍后继续状态。
- 第三方能按模板完成“首次私有预览”，且无需修改平台源码。
- 人物包导入导出、版本升级和来源撤销保持一致且可审计。

## 约束与非目标

- 首发公共人物只接受已故人物。
- 中文和 9–12 岁体验优先，底层协议保持多语言。
- 不为每个人物单独训练模型权重。
- 人物包不能携带任意可执行代码。
- AI 生成的知识不能绕过人工审核。
- MVP 不优先实现人物间自主聊天、开放插件市场、声音克隆或视频生成。
- 不把受版权保护的完整第三方材料默认复制或打包导出。
- 不在用户未明确加入时用私人对话生成公共训练数据。

## 主要风险

- 历史准确性与沉浸式角色表达冲突。
- 错误或过度主动的记忆产生不适感。
- 9–12 岁用户的身份、语音、聊天和画像带来更高隐私责任。
- 网络来源的可信度、许可和版本漂移难以治理。
- 同时建设对话、创作台、知识 Agent、语音和媒体导致范围失控。
- 新人物史料不足，社区供给质量参差不齐。
- 模型、Embedding 和多阶段核验影响延迟与成本。
- 外部模型 API 的稳定性、数据处理条款、区域可用性和供应商变化可能影响托管服务。

## 现有原型定位

现有 TypeScript monorepo、人物包 SDK、线程、消息、记忆、掌握度、规则 Agent Task、基础 API 与数据库迁移是可复用验证资产。JSON Store、规则型记忆与规则型 Agent 仍属于本地演示实现；正式身份、PostgreSQL Repository、语义召回、真实模型、网络来源发现、完整 Worker 和媒体 Provider 尚未成为生产能力。
