## 1. 设计结论

展厅页面从“Hero + 三张说明卡 + 人物列表”升级为一条纵向策展路线：

1. **入口序厅**：用场景、材料、轮廓和一个核心问题建立空间身份；
2. **核心物件**：用一件物件承接故事，只开放一个主要互动热点；
3. **人物关系**：解释谁与物件、事件或观点相连，再进入人物相遇；
4. **离场问题**：让用户带着一个问题离开或进入下一个展厅。

这里的“沉浸”来自连贯的环境、比例、叙事和物件，而不是连续动画、自动音效或重型 3D。

## 2. 页面信息架构

```text
全局访客导航（保持现状）
└── 展厅入口序厅
    ├── 时期 / 地点标牌
    ├── 展厅标题与核心问题
    ├── 场景图层（不可点击）
    ├── 唯一主动作：开始参观
    └── 四站路线指示
        ├── 01 入口
        ├── 02 核心物件
        ├── 03 人物关系
        └── 04 带走的问题

核心物件站
├── 物件舞台
├── 三层展签
│   ├── 它是什么
│   ├── 它见证了什么
│   └── 来源 / 表现性质
└── 主动作：顺着它认识人物

人物关系站
├── 默认 3 位最相关人物
├── 有文字的关系连接
└── 主动作：与一位人物相遇

离场区
├── 开放问题
├── 下一展厅
└── 返回时期馆
```

## 3. 入口序厅

### 桌面

- 首屏高度 55–70vh，不把整个屏幕封死；用户仍能看到下一站顶部，知道可以继续；
- 左侧是时期标牌、标题、核心问题和一个主按钮；
- 右侧是核心物件的空间轮廓，不直接显示完整说明；
- 背景分为远景建筑/地图、材料纹理、近景装饰三层；所有装饰层 `aria-hidden`；
- 底部四站路线是方向提示，不是四个同等醒目的按钮。

### 移动端

- 场景缩为 46–56vh；标题、问题和主按钮保持在稳定色板上；
- 只显示“第 1/4 站 · 入口”，点击后才展开完整路线；
- 物件轮廓位于标题下方，不与主按钮竞争；
- 首屏不出现人物横向轮播。

## 4. 核心物件交互

物件是本功能最重要的学习锚点。

### 默认状态

- 物件处于陈列台或展框中央；
- 显示名称、时代/地点和一句“为什么值得看”；
- 只有物件本体和“打开展签”属于同一交互目标；
- 辅助装饰不会出现 hover、光标或点击反馈。

### 展签状态

- 桌面从右侧打开 420–480px 抽屉；移动端从底部打开不超过 82vh 的抽屉；
- 第一屏只包含三个信息块：它是什么、它见证了什么、我们凭什么知道；
- 来源详细列表折叠在“查看来源”中；
- 历史重建和示意图使用显眼但克制的标签，不混同馆藏照片；
- 最下方只有一个主动作：“认识与它相关的人物”。

## 5. 人物关系站

- 人物头像作为“墙上肖像/展柜标签”嵌入空间，而不是重新出现一套卡册；
- 默认显示最相关 3 人，每人只展示姓名、关系短语和一个动作；
- 关系线必须配文字，如“共同参加会议”“作品记录战乱”“委托与赞助”；
- 未获得人物仍可进入引导式相遇；已获得人物可以继续长期对话；
- 人物相遇页头部继承展厅色条、物件缩略图和“返回第 3 站”。

## 6. 九个展厅的场景系统

### 盛唐与东亚交流

1. **长安：诗人与世界城市**
   - 远景：城门、坊市屋脊、路线灯点；
   - 材料：靛蓝夜色、暖金灯影、纸张；
   - 核心物件：有来源诗笺；
   - 动态：仅在允许动态时让路线灯点轻微显现，不漂浮诗句。
2. **佛法东行与丝路旅行**
   - 远景：沙路与海路线叠合、译场桌案；
   - 材料：沙金、孔雀蓝、麻纸；
   - 核心物件：经卷/译稿；
   - 不使用时代错误的现代导航罗盘作为主要符号。
3. **安史之乱：盛世为何转折**
   - 远景：断裂的道路与城市轮廓；
   - 材料：褪色朱红、烟灰、旧纸；
   - 核心物件：公文或诗稿；
   - 战争只通过档案、地图与人的处境表达，不使用武器和爆炸奇观。

### 文艺复兴与早期科学革命

1. **佛罗伦萨：艺术为何需要赞助人**
   - 远景：拱券、工作坊高窗、账册网格；
   - 材料：赭石、青绿、灰泥；
   - 核心物件：委托契约。
2. **罗马工作坊：大师如何竞争**
   - 远景：脚手架、半完成壁画、雕塑台；
   - 材料：石灰白、深红、木炭；
   - 核心物件：准备稿。
3. **从日心说到望远镜**
   - 远景：观测窗、星轨、印刷网点；
   - 材料：夜蓝、黄铜、羊皮纸；
   - 核心物件：望远镜或观测记录。

### 现代物理革命

1. **索尔维会议：自然是概率的吗**
   - 远景：会议室木桌、黑板、座签；
   - 材料：暖灰、胡桃木、粉笔白；
   - 核心物件：会议合影或合规艺术重建；
   - 人物按观点连接，不把会议呈现为名人合影墙。
2. **原子内部：理论与实验**
   - 远景：暗室、探测轨迹、仪器刻度；
   - 材料：实验室青绿、石墨黑、冷光；
   - 核心物件：金箔散射装置或云室图像。
3. **流亡、战争与科学责任**
   - 远景：档案柜、地图红线、空椅；
   - 材料：档案灰、褪色蓝、克制红；
   - 核心物件：流亡证件、书信或公开声明；
   - 不使用蘑菇云作为主视觉。

## 7. 轻快版与典藏版

| 维度 | 轻快版 | 典藏版 |
|---|---|---|
| 场景表现 | 分层绘本插画、清楚轮廓、较高明度 | 克制历史重建、材料纹理、局部展柜光 |
| 物件表现 | 大比例插画与短展签 | 真实获许可图像或写实重建与档案标签 |
| 字体 | 现有无衬线为主，标题可用温和展示体 | 无衬线正文 + 克制衬线标题 |
| 信息密度 | 默认 3 位人物、短标签 | 同样默认 3 位人物，可在同位置显示年代/来源摘要 |
| 动态 | 短入场淡入、路线点亮 | 更轻的光线与材质变化 |
| 功能与内容 | 完全相同 | 完全相同 |

视觉切换是 presentation preference，不是年龄或内容权限设置。

## 8. 视觉层级与 Design Token

平台保留现有海军蓝、纸白和红色主按钮。展厅新增三组受控 Token：

```css
--hall-bg-deep;
--hall-bg-soft;
--hall-surface;
--hall-ink;
--hall-accent;
--hall-highlight;
--hall-texture-opacity;
--hall-object-shadow;
```

- 展厅自定义值必须经过允许范围，不允许内容包注入任意 CSS；
- 正文位于 `--hall-surface` 上，不直接压在复杂背景上；
- 颜色不承担唯一语义，站点状态同时使用编号、文字和形状；
- 诗句作为 DOM `<blockquote>`，不得渲染为背景图片文字。

## 9. 动效

允许：

- 进入展厅时 180–260ms 淡入；
- 打开展签时短距离抽屉移动；
- 路线站点在进入视区时一次性点亮；
- 物件 hover/聚焦时 2–4px 位移或光线变化。

禁止：

- 无限漂浮、持续视差、烟雾、闪烁和粒子爆炸；
- 自动横向轮播；
- 用户滚动时大幅改变背景位置；
- 自动播放环境声。

`prefers-reduced-motion: reduce` 时全部改为无位移淡入或立即切换。该做法遵循 [W3C C39](https://www.w3.org/WAI/WCAG22/Techniques/css/C39)。

## 10. 错误、空状态与内容警示

| 状态 | 呈现 |
|---|---|
| 场景大图失败 | 保留主题渐变、结构轮廓、标题和路线，不出现空白大洞 |
| 核心物件图片失败 | 用已标注的物件剪影，展签文字和来源仍可打开 |
| 来源被撤销 | 物件退出公开陈列，显示“该展项正在重新整理”，不显示原图片 |
| 人物暂不可用 | 关系仍显示，动作改为“查看人物资料整理状态” |
| 慢网 | 先渲染文字与 CSS 场景，图片加载时固定尺寸，避免布局跳动 |
| 战争/迫害主题 | 入口显示一句内容提示，可继续或返回；不使用惊吓图像 |
| 无 JS / hydration 失败 | SSR 输出完整标题、物件标签、人物链接和来源链接 |

## 11. 可访问性

- 复杂场景中的正文保持至少 4.5:1，对大型文字保持 3:1；
- 装饰图层使用空替代文本或 `aria-hidden="true"`；
- 传达历史信息的图像提供简短替代文本，物件详情提供完整视觉说明；
- 物件舞台是有可见焦点的按钮，辅助装饰不是按钮；
- 抽屉管理焦点、支持 `Esc`，关闭后焦点回到物件；
- 页面放大至 200% 仍不丢失文字或控制；
- 不将诗句或标签烧录进背景图；
- 可选声音必须由用户主动开启，且提供字幕/文字等价物。

参考：[W3C Images Tutorial](https://www.w3.org/WAI/tutorials/images/)、[W3C Contrast Minimum](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum)。

## 12. 可用性评审脚本

1. 不解释页面，让测试者进入同一时期三个展厅，询问“它们分别在讲什么”；
2. 记录找到“开始参观”和核心物件的时间；
3. 让测试者从物件找到相关人物，并说明两者为什么有关；
4. 进入人物相遇后返回，确认回到同一站点；
5. 切换轻快版/典藏版，确认内容和进度一致；
6. 模拟背景失败、320–390px 宽度、200% 缩放和减少动态；
7. 询问哪些图像是真实史料、哪些是重建，验证标签是否清楚。

高保真访客导航 v7 进一步把登录、视觉模式、主页、历史探索、时期馆、沉浸展厅、人物介绍、长期对话、关系/时间与“我的博物馆”串成可点击闭环。设计稿顶部的 `DESIGN REVIEW` 跳转栏只用于评审，不属于正式产品界面。

设计板使用 CSS 与结构化文字模拟氛围，没有把其中的示意物件当成正式历史素材。

### 生成主视觉验证

九个展厅都已加入独立的历史主题艺术重建主视觉。每张图共享同一套博物馆编辑插画语言，但核心物件、材料、背景空间、光线和颜色由展厅主题决定，不通过简单换色复制。

- 唐代展厅使用诗卷、译经旅行和战乱文书组织三种不同空间。
- 文艺复兴展厅使用委托契约、工作坊准备稿、望远镜与印刷传播组织空间。
- 现代物理展厅使用会议争论、实验轨迹、流亡证件与书信组织空间。

## Post-Stage-5 Browser Remediation（唯一一轮）

- 移动端沉浸展厅、关系图与人物相遇使用页面内返回路径，不显示固定全局底栏，避免遮挡四站路线。
- 小屏顶部“显示”改为清楚的菜单图标，保留可访问名称，避免按钮文字被裁切。
- 轻快版模式卡改用明亮的儿童探索插画；典藏版继续使用克制的历史重建画面，两者不再只靠文字区分。
