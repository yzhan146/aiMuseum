# AI Museum 长期人物关系系统 — Stage 3 Gate

> 状态：等待 Gate 3 用户验收（2026-07-24）
> 上游决策：[`18-relationship-system-outcome-definition.md`](./18-relationship-system-outcome-definition.md)、[`19-relationship-system-solution-definition.md`](./19-relationship-system-solution-definition.md)
> 本文只申请进入用户验收，不代表已获准发布。

## 1. 本阶段交付

- 五个可见关系阶段：初识、相知、小友、老友、莫逆之交。
- 每个阶段使用已批准的青黛色板，并始终同时显示完整文字，不用颜色单独传达含义。
- 人物页与长期对话页显示关系标签；关系抽屉提供暂停、恢复、称呼管理、记忆入口与关系重置。
- 晋级反馈以一次性的对话内里程碑呈现，不显示分数、门槛、权重、进度或攻略。
- 服务端采用来源绑定的证据账本、确定性投影和每次最多晋升一级的阶段机。
- 当前关系阶段、称呼许可与经过验证的共同经历在生成前进入行为合同；暂停时不注入，也不产生新关系证据或关系记忆。
- 模型与页面都持续说明这是 AI 历史人物演绎，不冒充真人。
- 未解锁人物不能通过直接调用聊天或线程写接口建立长期关系；所有写入口要求同源请求。
- 重置保留聊天消息，但清除关系证据、阶段历史、称呼许可和关系记忆，并以独立 recording revision 阻止在途旧回合穿越重置边界。
- 访客登录合并遵守账户 reset cutoff，先规范化 learning-event 来源与 logical key，再做确定性重投影；旧晋级反馈不重放。
- 线程删除会先删除关系聚合，再删除消息；账户导出包含机器可读的关系阶段、历史、证据、来源、内部派生量与称呼许可；账户永久删除会清除关系派生数据。

## 2. 公开与内部边界

用户可见：

- 当前阶段文字与颜色；
- 阶段变化后的单次反馈；
- 暂停状态、已许可称呼和可管理记忆；
- “AI 历史人物演绎”身份说明。

普通产品 UI 与公开关系 API 不显示：

- 关系分值、维度、门槛、权重、证据质量和下一阶段条件；
- 哪句话贡献了多少进度；
- 可被当作任务清单的晋级攻略。

内部量化仅存在于受控存储、账户导出和未来的维护/Eval 工具中。

## 4. 建议的 Gate 3 人工验收

1. 人物页与聊天页的关系标签是否清楚、温和，不像抽卡稀有度或可刷进度条。
2. 五阶段色彩是否能辅助感知变化，同时不压过阶段文字。
3. 关系抽屉是否清楚说明“不会展示具体条件”，暂停与重置的后果是否容易理解。
4. 关系变化是否表现为称呼、承接、追问和分歧方式的变化，而不只是换标签。
5. 里程碑反馈是否有成就感，但不会打断对话或暗示下一阶段攻略。
6. AI 身份说明是否足够明确，又不破坏沉浸感。
7. 账户页的数据导出与永久删除说明是否让关系记录处于用户控制之下。

## 5. Gate 4 发布前阻塞项

以下事项不阻止本地 Stage 3 产品验收，但在发布前必须完成：

- 运行真实 PostgreSQL migration，并覆盖 guest merge、reset cutoff、deferred FK、并发 outbox claim、线程/账户删除与导出完整性的集成测试。
- 提供持续运行的 relationship outbox consumer；当前聊天后的异步 drain 不能保证失败任务在没有后续聊天时继续重试或回收。
- 使用真实模型完成五阶段行为 Eval、人物风格对照、记忆来源真实性和 anti-gaming 校准。
- 在生产配置下完成 destructive-flow E2E、数据导出核对、可访问性与移动端回归。
- 在发布指标和告警就绪后再决定是否开放全部人物，仍以一个锚点人物纵向闭环为默认上线策略。
