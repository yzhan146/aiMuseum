# AI Museum 账户系统设计

- 状态：实现前基线
- 范围：访客身份、邮箱注册、登录、验证、密码重置、数据合并与线上持久化

## 1. 决策

首版采用“邮箱 + 密码”注册，昵称只用于展示，不作为登录标识。邮箱天然提供找回路径，也避免用户名被占用、改名和忘记用户名造成的额外流程。微信、Google 等第三方登录延后，不改变稳定的内部 `user_id`。

注册与找回均使用邮件中的一次性链接，不要求用户手抄验证码：

1. 访客可以直接体验，系统通过 HttpOnly Cookie 分配匿名身份。
2. 用户注册时提交邮箱、展示昵称和密码。
3. 服务端创建未验证账户并发送验证链接；验证前可以继续当前设备上的体验，但不允许高风险操作。
4. 验证成功后建立账户会话，并将当前访客的线程、消息、记忆、掌握度、星星、碎片和人物收藏幂等合并到账号。
5. 登录后所有 API 只使用服务端会话解析出的 `user_id`，客户端不得自行传入用户 ID。
6. 忘记密码时始终显示相同结果；若邮箱存在，发送短时、单次使用的重置链接。
7. 重置成功后撤销该用户的其他会话，当前设备重新登录。

## 2. 为什么不直接上线现有访客存储

现有 `museum_guest` Cookie 已能让不同浏览器拥有不同的聊天历史和人物收藏，`mergeGuestIntoUser` 也已具备访客合并语义。但运行数据仍写入 `data/runtime/platform.json`。它适合本地原型，不适合 Render 多实例或会被重建的文件系统。

正式账户上线的前置条件是：

- PostgreSQL 成为用户、线程、消息、记忆、掌握度、卡牌资产和认证状态的记录源；
- 每个写操作使用事务和唯一约束保证幂等；
- 邮件 Provider 完成域名验证，密钥只保存在部署环境变量中；
- 删除、导出、封禁和审计以稳定 `user_id` 为边界。

## 3. 数据模型

迁移文件 `infra/migrations/003_accounts.sql` 新增：

- `auth_credentials`：规范化邮箱、密码哈希、邮箱验证和锁定状态；
- `auth_sessions`：只保存随机会话密钥的哈希、有效期和撤销状态；
- `auth_email_tokens`：验证邮箱和重置密码使用的单次、短时令牌哈希。

业务表继续引用稳定的 `users.id`。邮箱、昵称和当前会话都不是数据归属键，因此改邮箱、改昵称或退出登录不会改变历史归属。

## 4. 安全基线

- 密码哈希优先 Argon2id；运行环境不具备可靠 Argon2 实现时使用参数充分的 scrypt。数据库只保存 PHC 格式的哈希，不可逆加密不是密码存储方案。
- 接受长密码和 Unicode，不设置“必须含大小写与符号”一类组合规则；使用常见和已泄露密码阻止列表。
- 登录、注册、验证邮件和重置邮件都限速。登录与找回返回通用文案，不泄露某邮箱是否存在。
- 会话 Cookie 使用 `HttpOnly; Secure; SameSite=Lax`，密钥由密码学安全随机数生成；数据库只保存其哈希。
- 邮件令牌随机生成、只使用一次、过期即失效；重新申请时旧令牌作废。
- 聊天内容、儿童画像和人物记忆不进入认证日志或邮件 Provider。

## 5. 页面与用户流程

### 5.1 访客状态

全局导航显示“保存进度”。点击后打开轻量账户面板，解释注册会永久保存：人物对话、历史发现、人物收藏、星星和学习进度。用户关闭面板后继续访客体验，不强制中断。

### 5.2 注册

一个页面最多呈现三个关注点：

1. 邮箱；
2. 展示昵称；
3. 密码与“创建账户”。

提交后进入“查收验证邮件”状态，提供重新发送和更换邮箱。验证链接回到原页面，并显示访客数据合并摘要。

### 5.3 登录

输入邮箱和密码；错误只显示“邮箱或密码不正确”。登录成功后回到打开账户面板前的页面，而不是固定跳回主页。

### 5.4 忘记与重置密码

“忘记密码”只要求邮箱。无论账号是否存在都显示“如果这个邮箱已注册，你会收到邮件”。重置页输入两次新密码；成功后撤销旧会话，清楚说明需要重新登录。

### 5.5 账户中心

首版只包含三组：个人资料、数据与隐私、账户安全。用户可以修改昵称、查看验证邮箱、导出数据、删除账户、退出当前设备或退出全部设备。

## 6. API 合约

- `POST /api/auth/register`
- `POST /api/auth/verify-email`
- `POST /api/auth/resend-verification`
- `POST /api/auth/login`
- `POST /api/auth/logout`
- `POST /api/auth/logout-all`
- `POST /api/auth/forgot-password`
- `POST /api/auth/reset-password`
- `GET /api/account`
- `PATCH /api/account/profile`

所有认证写接口都需要 CSRF/Origin 校验、IP 与账号维度限速和结构化审计事件。响应不返回密码哈希、令牌、会话密钥或内部风控状态。

## 7. 实施顺序

1. 将 `platform-store` 替换成 PostgreSQL Repository，并保持现有测试所用的内存实现。
2. 执行账户迁移，实现密码、令牌、会话和邮件 Provider 接口。
3. 接入注册、验证、登录、找回与账户中心 UI。
4. 在事务中调用访客合并，并补充重复点击、并发登录和合并冲突测试。
5. 在 Render 测试重启、重新部署、过期链接、撤销会话和多用户隔离。

在 PostgreSQL 和邮件发送账号确定之前，不应把本地 JSON 认证作为“正式账户系统”发布。
