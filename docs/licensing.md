# AI Museum 许可与内容权利指南

本文件说明仓库中不同类型内容应当使用什么许可。它是项目政策，不构成针对具体情况的法律意见；对权属不确定的内容，应在发布前获得专业法律建议。

## 1. 平台代码

平台代码、SDK、Worker、基础设施配置和未另行声明的第一方开发文档采用 `Apache-2.0`。

Apache-2.0 允许使用、修改、分发、商业使用和私有使用，也提供明确的贡献者专利授权。重新分发时必须保留许可证与适用的 NOTICE，修改文件还应标明变更。许可证不授予商标权。

## 2. 人物包不是平台代码

每个人物包必须在 `manifest` 中独立声明：

- `license`：人物包原创文字与结构化数据的许可证；
- `authors`：作者和维护者；
- `sourceLicenses`：来源材料各自的权利状态；
- `mediaPermissions`：展示、转码、训练、声音合成、形象生成等分项权限；
- `attributions`：作者、馆藏机构、作品名、来源 URL、许可与修改说明。

建议的开放许可：

| 内容 | 建议 | 说明 |
|---|---|---|
| 原创人物包文字与策展结构 | `CC-BY-4.0` | 允许再利用，但必须署名 |
| 希望最大程度开放的原创元数据 | `CC0-1.0` | 尽可能放弃权利限制；提交者必须有权这样做 |
| 已确认属于公共领域的作品 | `PDM-1.0` 状态标记 | 这是权利状态标记，不是把他人作品重新许可为 CC0 |
| 平台模板和示例代码 | `Apache-2.0` | 与平台代码一致 |
| 权属不清或禁止再发布的材料 | 不打包 | 只保存来源信息、允许的摘录和处理结果 |

不要把 `CC-BY-NC`、`CC-BY-ND` 或仅限教育使用的内容标记为“开源”。它们可以作为受限素材被平台引用，但不能进入默认开放人物包，且必须在界面和导出中保留限制。

## 3. 史料、摘录和网页

历史事实本身与具体文字、照片、录音或数据库编排的权利不是一回事。录入事实不能证明有权复制来源的表达形式。

- 默认只保存来源元数据、定位、处理结果和必要的短摘录；
- 不使用“网上能看到”作为再发布许可；
- 删除来源或撤销许可时，重新计算受其支持的 Claim；
- 每个摘录保存适用辖区、使用依据和审核记录；
- 需要合理使用、法定许可等判断时，保持私有并交由人工审核。

## 4. 图片、肖像、声音与生成媒体

一项资产的权限必须拆开记录，不能用单一“已授权”代替：

- 原样展示；
- 裁切、修复和转码；
- 训练或微调；
- 生成相似形象；
- 声音合成；
- 商业使用；
- 再分发与人物包导出。

卡通形象、写实复原和历史肖像还必须标记为 `artistic_interpretation`、`evidence_based_reconstruction` 或 `historical_portrait`。推测复原不得呈现为真实照片。

生成媒体需要记录生成服务、模型、日期、输入素材、授权依据和服务条款版本。平台不能假定 AI 生成内容在所有地区都具有相同的版权状态。

## 5. 第三方依赖

`package-lock.json` 中的第三方软件继续适用各自许可证。源码仓库不通过 Apache-2.0 重新许可这些依赖。制作容器、桌面应用或其他二进制发行物时，应生成依赖清单/SBOM，并把必须保留的第三方许可与通知放入发行物。

## 6. 贡献

除贡献者明确标记为“Not a Contribution”或另有书面协议外，提交给平台代码库并被接收的贡献按照 Apache-2.0 第5节处理。贡献者仍保有自己贡献的版权。

人物包和媒体贡献必须同时提交独立的许可与来源信息。缺少权属证明、许可字段或来源定位的内容只能停留在私有草稿或审核区。

## 7. 发布前许可检查

- 根目录包含完整 `LICENSE` 和 `NOTICE`；
- npm 包使用正确的 SPDX 标识；
- 每个人物包都声明许可、作者与兼容版本；
- 每项媒体都有来源、权利状态和分项权限；
- 导出包不包含禁止再发布的原始材料；
- 构建产物包含适用的第三方通知；
- README 清楚区分软件许可和内容许可。
